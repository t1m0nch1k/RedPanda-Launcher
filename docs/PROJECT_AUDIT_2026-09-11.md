**Подробный анализ проблем RedPanda Launcher**

Дата: 11 сентября 2026 года. Проверенная ревизия: `adbf309`, версия проекта `0.3.0`.

Главные риски проекта — потеря файлов при установке, нарушение связности данных при миграции сборок и ложное сообщение об успешной сборке модпака. Компиляция интерфейсов и успешные unit-тесты не подтверждают корректность этих пользовательских сценариев.

## Статус исправлений

Все 17 пунктов этого аудита исправлены в рабочем дереве после первичного анализа. В том числе установщик теперь работает только с проверяемым манифестом собственных файлов, обновление сборки и импорт публикуют результат лишь после успешных загрузок, а токены обновляются с сохранением на диск. Для Forge и NeoForge восстановлен корректный формат `.mrpack`; загрузки Modrinth и CurseForge записываются потоково с проверкой хеша и лимита размера.

CI и release workflow теперь устанавливают зависимости каждого подпроекта, запускают проверки качества на тегах и публикуют новый release как черновик до верификации всех подписанных assets. CSP ограничен управляемыми каталогами приложения и разрешает нужные CDN изображений. Исправлены локали ES и ZH, поддержка `_fixN` в тегах, а также добавлены регрессионные тесты для миграции ID, загрузок, обновлений и безопасного установщика.

Повторно выполнены: `npm run build`, сборка installer, lint и production build сайта, `scripts/check-version.ps1` (включая `v0.3.0_fix2`), `scripts/check-locales.ps1`, форматирование, строгий Clippy и unit-тесты. Пройдены 27 тестов основного Rust-модуля и 5 тестов установщика. Реальный сетевой вход, запуск Minecraft, подпись релиза и установка на чистом пользовательском профиле по-прежнему требуют отдельной интеграционной проверки.

После проверки пользовательских скриншотов дополнительно исправлены дефекты каталога:

- удалён экранный ввод собственного ключа CurseForge; встроенный ключ остаётся основным, а служебная переменная `CURSEFORGE_API_KEY` сохранена для автоматизированных развёртываний;
- в CSP добавлены CDN изображений Modrinth и CurseForge, поэтому карточки больше не должны показывать сломанные иконки;
- исправлен заголовок списка версий CurseForge, который отображался как необработанный ключ `modrinth.versions`;
- для CurseForge используется правильное значение `HashAlgo` (SHA-1 — `algo: 1`), хеш передаётся из ответа API во все пути установки и проверяется потоково до публикации файла. Это устраняет ложное сообщение об отсутствии checksum для файлов, у которых SHA-1 присутствует.

Проверка после этих изменений: `npm run build`, `cargo test --manifest-path src-tauri/Cargo.toml --locked --lib` (27 тестов), `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check` и `git diff --check` завершились успешно.

Анализ охватывает основной React/Tauri-лаунчер, Rust-ядро, собственный установщик, конфигурацию обновлений и CI. Для сайта выполнены lint и production build; глубокой проверки его содержания, доступности и SEO не было. Проморолик, старые копии и опубликованные бинарники не проверялись. Использован локальный граф архитектуры и исходный код. Функциональные дефекты ниже подтверждены статическим прослеживанием путей выполнения; разрушительные сценарии на пользовательских каталогах не запускались. Сетевой вход Microsoft/Ely.by, реальный запуск Minecraft и установка/удаление приложения не выполнялись. Актуальные CVE зависимостей не исследовались.

**1. P1 — установщик может удалить посторонние файлы из выбранной папки**

Источники: [installer/src/App.tsx](<C:/Users/artem/Desktop/RedPanda Launcher/installer/src/App.tsx:76>), [installer/src-tauri/src/installer.rs](<C:/Users/artem/Desktop/RedPanda Launcher/installer/src-tauri/src/installer.rs:163>), [installer/src-tauri/src/installer.rs](<C:/Users/artem/Desktop/RedPanda Launcher/installer/src-tauri/src/installer.rs:245>).

Диалог выбора возвращает каталог напрямую в `installPath`. Backend проверяет абсолютность пути и запрет корня диска, но не принадлежность каталога приложению. Если каталог уже существует, он целиком переименовывается в backup; вместо него публикуется распакованный payload, затем backup рекурсивно удаляется.

Сценарий: пользователь выбирает существующую папку с другими приложениями или документами. При наличии прав и отсутствии блокировок установка удалит всё прежнее содержимое этой папки. Проверка свободного места и staging от этого не защищают.

Исправление: устанавливать в отдельный дочерний каталог; обновление разрешать только для каталога с проверяемым маркером установки. Не удалять файлы, отсутствующие в манифесте приложения. Регрессионная проверка: временная папка с посторонним sentinel-файлом должна сохраняться либо установка должна отклоняться.

**2. P1 — миграция идентификаторов может отвязать сборку от её файлов и создать коллизии**

Источник: [src-tauri/src/instances.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/instances.rs:57>).

`read_instances_unlocked` меняет UUID и не-ASCII ID при обычном чтении списка. Неудача `fs::rename` лишь логируется, после чего `instance.id` всё равно заменяется и записывается. Если новый каталог уже существует, переименование вообще пропускается, но новый ID всё равно принимается.

Кроме того, уникальность проверяется только относительно уже обработанного `migrated_instances`, а не полного исходного списка. Старый UUID с именем «Pack» перед существующим ID `pack` может превратиться в тот же `pack`. Тогда две записи ссылаются на одну папку, а исходная папка первой сборки остаётся отдельно. Последующее удаление по ID затрагивает обе записи.

Исправление: отдельная транзакционная миграция, резервирование ID по полному списку и файловой системе, сохранение старого ID при ошибке. Чтение списка не должно выполнять необратимые миграции. Проверки: отказ переименования, занятый целевой каталог и разный порядок записей.

**3. P1 — конструктор модпаков сообщает об успехе при неполном результате**

Источники: [src-tauri/src/builder.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/builder.rs:475>), [src-tauri/src/builder.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/builder.rs:513>).

Не найденная версия мода превращается в предупреждение. HTTP-ошибки, ошибки чтения ответа, превышение размера, неверный checksum и ошибка записи не приводят к отказу всей операции. Для записи используется `let _ = fs::write(...)`. После цикла безусловно отправляется `status: "done"` и возвращается `Ok(instance)`.

Пользователь получает «Сборка успешно создана», хотя обязательный мод отсутствует или файл записан частично. Ошибка проявляется значительно позже, при запуске Minecraft.

Исправление: накапливать ошибки разрешения и скачивания, проверять полный набор обязательных артефактов, скачивать во временный каталог и публиковать сборку только после проверки. При 404, неверном хеше или отказе записи результат не должен иметь статус success.

**4. P1 — экспорт Forge/NeoForge не проходит собственный импорт с сохранением загрузчика**

Источники: [src-tauri/src/instances.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/instances.rs:1231>), [src-tauri/src/import.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/import.rs:133>).

Экспорт строит ключ зависимости как `format!("{}-loader", loader_type.to_lowercase())`. Для Forge получается `forge-loader`, для NeoForge — `neoforge-loader`. Импорт проверяет ключи `forge` и `neoforge`. При их отсутствии выбирается Vanilla.

Следовательно, цикл «экспортировать Forge/NeoForge в mrpack → импортировать» теряет тип загрузчика; скопированные моды оказываются в Vanilla-сборке.

Исправление: явное сопоставление четырёх загрузчиков с ключами формата и общий модуль сериализации. Проверка: экспорт/импорт для каждого загрузчика должен сохранять Minecraft version, loader type и loader version.

**5. P1 — обновление токенов при запуске не сохраняется, ошибки скрываются**

Источники: [src-tauri/src/launcher.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/launcher.rs:202>), [src-tauri/src/accounts.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/accounts.rs:866>), [src/pages/Home.tsx](<C:/Users/artem/Desktop/RedPanda Launcher/src/pages/Home.tsx:498>).

Запуск загружает аккаунт, вызывает `refresh_account_tokens` для локальной копии и использует её дальше. Сохранения обновлённых access/refresh token и срока действия в этом пути нет. Параметр функции `_app` не используется. Отдельная команда `validate_and_refresh_account` сохраняет результат, но основной frontend-путь её не вызывает.

Конструкция `if let Ok(true)` также игнорирует ошибку обновления. Неуспешный HTTP-ответ внутри refresh нередко становится `Ok(false)`, и запуск продолжается со старым токеном.

Последствия: повторные refresh при следующих запусках, возможная потеря актуального refresh token при его ротации, неясные ошибки сетевой авторизации. Исправление: единая операция обновления и сохранения аккаунта с явным результатом «нужен повторный вход».

**6. P2 — разрешение зависимостей не проверяет конфликты обязательных версий**

Источник: [src-tauri/src/builder.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/builder.rs:329>), [src-tauri/src/builder.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/builder.rs:447>).

Это может работать за счёт поиска инструментов и совпадающих зависимостей в родительском node_modules, но не проверяет самостоятельную сборку по installer/package-lock.json.

Исправление: восстановить прохождение существующих проверок и отдельно устанавливать зависимости каждого проекта. Не ослаблять -D warnings ради зелёного статуса.

**14. P2 — релиз публикуется независимо от CI, замена assets неатомарна**

Источник: [.github/workflows/release.yml](<C:/Users/artem/Desktop/RedPanda Launcher/.github/workflows/release.yml:1>), [.github/workflows/release.yml](<C:/Users/artem/Desktop/RedPanda Launcher/.github/workflows/release.yml:125>).

Release workflow запускается по тегу и не содержит зависимости от результатов CI; CI настроен на main и pull request. Тег можно собрать без успешного прохождения всех проверок.

При публикации новый release создаётся сразу с draft:false; существующие assets удаляются до загрузки новых. Ошибка сети или API между удалением и завершением загрузок оставит релиз пустым либо без части manifest/signature/installer.

Исправление: обязательный quality gate для тегируемой ревизии, подготовка draft-release и публикация после проверки всех артефактов. Для замены действующего релиза нужен план восстановления прежних assets.

**15. P2 — первый импорт зависит от наличия игрового каталога**

Источник: [src-tauri/src/import.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/import.rs:153>), [src-tauri/src/import.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/import.rs:476>).

Оба импортера создают staging через `tempdir_in(data_dir)`, не создавая предварительно сам data_dir. `add_instance` записывает метаданные в Tauri-каталог, отличный от `Roaming/RedPandaLauncher`.

На профиле, где игровой каталог ещё не создан другим действием, импорт завершится ошибкой создания staging. Это условный сценарий, выводимый из кода; чистый Windows-профиль не запускался.

Исправление: явная инициализация каталогов перед началом операции; проверить импорт первым действием после установки. Запись готовой сборки в общий список выполнять после успешной публикации файлов.

**16. P2 — fallback хранения секретов ослабляет защиту и скрывает ошибки**

Источник: [src-tauri/src/accounts.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/accounts.rs:42>), [src-tauri/src/accounts.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/accounts.rs:128>).

На Windows основной путь использует DPAPI. При его отказе код автоматически переходит к AES с ключом, вычисленным из пути config_dir и фиксированной строки. Такой ключ восстанавливается из известных данных; случайный nonce не делает сам ключ секретным. В конце encrypt_secret также существует возврат исходной строки, а ошибки расшифровки возвращают исходный ciphertext как будто это токен.

Это не утверждение, что текущие аккаунты хранятся открыто: обычный Windows-путь использует DPAPI. Проблема в поведении при отказе и поддержке слабого legacy fallback.

Исправление: возвращать Result при ошибке защиты/расшифровки, не записывать новый секрет с пониженной защитой без явной политики, мигрировать legacy-формат после успешного чтения.

**17. P3 — тесты не покрывают критические операции с пользовательскими данными**

Источники: [src-tauri/src/instances.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/instances.rs:1401>), [src-tauri/src/updater.rs](<C:/Users/artem/Desktop/RedPanda Launcher/src-tauri/src/updater.rs:370>), [installer/src-tauri/src/installer.rs](<C:/Users/artem/Desktop/RedPanda Launcher/installer/src-tauri/src/installer.rs:548>), [package.json](<C:/Users/artem/Desktop/RedPanda Launcher/package.json:6>).

15 выполненных тестов ядра проверяют главным образом валидацию путей, хеши, транслитерацию, запись JSON и несколько сравнений версий. Тест кириллического пути проходит без проверки, если конкретная папка пользователя отсутствует. У установщика обнаружен тест подсчёта размера каталога, но не удаления/обновления. В package.json лаунчера нет команды UI-тестов.

Само небольшое число тестов не является дефектом. Проблема в отсутствии проверок наиболее рискованных контрактов: сохранности посторонних файлов, миграции ID, экспорта/импорта, failure-path скачивания, сохранения токенов и нестандартного install path.

**Архитектурные причины**

Хранилище разнесено между игровым каталогом и двумя Tauri-каталогами, при этом установщик содержит собственные строковые пути. Поэтому установка, удаление, миграция и импорт расходятся в представлении о данных приложения.

Слой скачивания тоже неоднороден: downloads.rs содержит потоковую проверяемую загрузку, но builder, import и modrinth реализуют свои циклы и различную обработку ошибок. В builder проверка хеша есть, но её отказ не доходит до UI.

Чтение instances.json выполняет миграцию путей и подбор loader version. Побочные эффекты обычного чтения усложняют восстановление и делают ошибки порядка записей опасными.

Типизированный IPC-слой существует, но Home продолжает разбирать события через any и строки. Статическая проверка frontend не гарантирует соответствие событий Rust и UI. Стоит постепенно свести команды и события к общему контракту.
