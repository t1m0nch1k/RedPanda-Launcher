## P1 — критические

### 1. Сборки без переменной окружения вшивают публичный тестовый ключ подписи обновлений

`src-tauri/build.rs:12-18`: если `REDPANDA_UPDATE_PUBLIC_KEY_HEX` не задана, в бинарник попадает ключ `d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a` — публичная половина тест-вектора RFC 8032, приватная половина которого широко известна. `scripts/build-custom-installer.ps1:13-15` подставляет этот же ключ по умолчанию.

Следствие: у любой локально собранной версии (в том числе у установленной сейчас 0.3.3) проверка подписи манифеста обновления не даёт защиты — подпись можно подделать известным приватным ключом. Релизный путь в CI закрыт: ключ приходит из `vars`, а шаг подписи падает, если переменные не заданы (`release.yml`), поэтому официальные сборки этим не затронуты.

Как исправить: сделать ключ обязательным для релизной сборки (падать, а не подставлять тестовый), либо явно предупреждать в выводе сборки о тестовом ключе.

### 2. Токен Telegram-бота закоммичен в открытом виде

`scripts/send-telegram-announcement.ps1:3` — значение по умолчанию для `$BotToken` записано литералом и попало в историю git (в отчёте не приводится). Тот же файл-скрипт используется для анонсов в канал `@redpanda_launcher`.

Как исправить: отозвать токен у @BotFather, выдавать новый и передавать его через окружение — как уже сделано в `scripts/publish-telegram.py` (читает `TELEGRAM_BOT_TOKEN` из `.env`). Прежний токен считать скомпрометированным, даже после правки файла.

## P2 — существенное

### 3. Запуск по ярлыку обходит защиту от второго экземпляра

`src-tauri/src/lib.rs:41-56`: если передан `--launch-instance`, мьютекс единственного экземпляра не берётся. `src-tauri/src/instances.rs:1590` создаёт ярлык именно с этим аргументом.

Следствие: при уже открытом лаунчере ярлык поднимает второй процесс, который запускает игру и параллельно пишет в те же `instances.json` / `accounts.json` / `settings.json` (включая обновление токенов). Возможна молчаливая потеря только что сохранённых изменений.

### 4. Ключ CurseForge вшит в бинарник

`src-tauri/src/curseforge.rs:67` — `DEFAULT_CURSEFORGE_API_KEY` как основная константа; ключ извлекается из exe. Запасной путь через переменную окружения и повтор запроса есть (`curseforge.rs:103-116`), то есть решение осознанное, но последствие реальное: при блокировке или отзыве ключа каталог CurseForge сломается у всех пользователей сразу, и это не исправляется обновлением кода.

### 5. Деинсталляция не закрывает запущенный лаунчер и глушит ошибки удаления

`installer/src/App.tsx:163-190` — в сценарии удаления нет вызова `close_running_launcher` (при установке он есть: `App.tsx:51,100`). `installer/src-tauri/src/installer.rs:786-818` удаляет файлы скриптом PowerShell с `-ErrorAction SilentlyContinue`.

Следствие: если лаунчер открыт, исполняемый файл остаётся на диске, а ярлыки и запись в реестре уже удалены — пользователь видит «успешно удалено», но папка с приложением остаётся. Уточнение: интерфейс всё же показывает ошибку, если команда вернула отказ (`App.tsx:183-189`), — безусловного «успеха» нет.

## P3 — мелочи, которые стоит знать

- `src/pages/Home.tsx:442-446`: при перетаскивании `.zip` вызовы `is_curseforge_pack` / `import_curseforge_pack` идут без `try/catch` (в ветках `.jar` и `.mrpack` обработка есть) — при отказе пользователь не получает никакого сообщения.
- i18n: `common.delete` (`src/components/AccountSelector.tsx:179`, всплывающая подсказка) и `modrinth.no_compatible_versions_modpack` (`src/components/ModrinthBrowser.tsx:344`, сообщение каталога) отсутствуют во всех четырёх локалях и не имеют `defaultValue` — пользователь увидит сырой ключ. Ещё два ключа из отчёта ревьюера (`settings.tab_general`, `settings.tab_java`) имеют запасной текст в самом вызове — дефекта нет.
- `src-tauri/src/discord.rs`: 8 вызовов `.lock().unwrap()`. Паника в любом месте под блокировкой отравит мьютекс, и все последующие вызовы Discord RPC начнут падать.
- `src-tauri/src/instances.rs:1463`: `path.strip_prefix(&inst_dir).unwrap()` при обходе каталога. Сейчас безопасно (путь всегда из `WalkDir` по тому же корню), но дешевле заменить на `continue`.
- `src-tauri/src/java.rs:49`: `ensure_java_runtime` не вызывается ниоткуда — автоскачивание JRE с проверкой хеша недостижимо (мёртвый код).
- `src-tauri/src/launcher.rs:522`: адрес сервера подставляется в URL стороннего API (`api.mcstatus.io`) без экранирования.
- `installer/src-tauri/src/installer.rs:777-839`: скрипты удаления собираются конкатенацией путей; сейчас значения приходят из проверенного манифеста и проходят `powershell_literal`, но место хрупкое к будущим правкам.

## Проверено и чисто

- **Пути.** `security::safe_join` отклоняет `..`, корневые компоненты, префиксы диска и ссылки/reparse-точки на всём пути. `validate_instance_id` и `validate_filename` запрещают разделители, `..`, управляющие символы, зарезервированные имена Windows, хвостовые точку и пробел.
- **Распаковка архивов.** `import.rs:209`, `backup.rs:154`, `java.rs:142` — `enclosed_name()`, а результат дополнительно проходит через `safe_join`, то есть защита от zip-slip продублирована.
- **Запись данных.** `storage::atomic_write` пишет во временный файл, делает бэкап и заменяет через `MoveFileExW` с `MOVEFILE_REPLACE_EXISTING`; `read_json_with_backup` восстанавливает данные из бэкапа и сохраняет повреждённый файл отдельно. Есть регрессионный тест.
- **Обновления.** `updater.rs`: подпись манифеста проверяется ed25519, дополнительно проверяются hex-формат и размер SHA-256, имя ассета, и без подписи обновление не предлагается; тест `rejects_invalid_manifest_signature` проходит.
- **Стык IPC.** Имена и аргументы команд совпадают; `dangerouslySetInnerHTML`/`innerHTML`/`eval` не используются; единственный `JSON.parse` — в `try/catch`.
- **Ранее заявленные исправления** (аудит `docs/PROJECT_AUDIT_2026-09-11.md`, пункты по установщику, деинсталляции, миграции идентификаторов сборок, загрузкам и обновлениям) в текущем коде на месте, регрессий не обнаружено.

## Опровергнутое (проверял — не подтвердилось)

- **Мнимый дедлок в `discord.rs`.** В `clear_discord_activity` блокировка `start_time` берётся временной и освобождается до взятия `client`, поэтому порядок захвата «client → start_time» сохраняется в обоих путях. ABBA-дедлока нет.
- **Мнимые расхождения IPC.** Механическая сверка нашла 0 расхождений; единственная «пропавшая» команда `save_instance_settings` существует (`instances.rs:1067`) и зарегистрирована (`lib.rs:127`) — ошибка была в моём разборе, а не в коде.
- **Мнимые паники.** `launcher.rs:298` (`strip_prefix('-').unwrap()`) стоит под проверкой `arg.starts_with('-')`; `panic!`, `todo!`, `unimplemented!` в ядре отсутствуют.
